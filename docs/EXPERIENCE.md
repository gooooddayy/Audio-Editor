# 开发经验与踩坑记录

> 本文是「换新电脑后继续开发」的核心参考资料：记录这个工具为什么长成现在这样、踩过哪些坑、需求演化过程。
> **铁律：迭代历史里被移除的功能，没有业主确认不要加回来。**

## 1. 迭代历史（为什么代码是现在这样）

### v1 音频裁剪工具（2026-07-27）

最初需求：波形显示 + 双手柄自由裁剪 + 淡入淡出滑块 + 磁吸吸附 + WAV 导出。

关键决策：

- 峰值只算一次、拖拽时只重绘不重算 → 流畅
- 磁吸用「30ms 窗口内最近零交叉点」而不是贴时间刻度——这是消爆音最专业的做法
- 导出用 `OfflineAudioContext` 离线渲染，保证「导出 = 试听」

### v2 多段分割编辑器（同日重写）

需求升级：滚轮缩放 + 0.5/0.75/1/2/3 倍速 + 自由位置多次分割 + 逐段淡变 + 删除自动拼接 + 整包导出。

段模型改为 `{start, end, fadeIn, fadeOut}`；删除后段间在源时间留空、输出时拼接。

### v3 时间轴模型（核心重写）

新需求暴露出 v2 模型不够用，改为 `{s, e, pos, fi, fo}`：

- `s/e` = 原音频时间；`pos` = 输出时间轴位置——**两套坐标系分离**
- 由此获得：从光标位置播放、删除后 `pos` 前移闭合空白、片段独立定位
- 新增 **3ms 微淡变（MICRO_FADE）**：没有用户淡变的段边界也加微淡入/淡出，专治拼接「咔哒」声
- 选段从数组下标改为 `selectedId`，避免排序/增删后引用错乱

### v4 交互精简（2026-07-28，两次迭代）

- 光标线时间改为 `mm:ss:mmm` 格式（新增 `fmtTime`）；淡变上限 3s → 5s
- 业主主动要求**移除长按拖动片段**功能（连带删掉 `dragState` / `pressTimer` / `resolveOverlaps`）
- 一度放开缩放边界限制（波形可移出画布），**最终决定完全取消缩放/平移**：删掉滚轮缩放、拖拽平移、「适应」按钮，交互回归「点击放光标」，视图恒为全宽

教训：这个项目的功能是**逐步收敛**的，不是逐步堆砌的。每加一个交互先问「业主真的需要吗」。

## 2. Web Audio API 踩坑

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | AudioContext 创建后被浏览器挂起（suspended） | 必须在用户手势中创建/恢复；本项目把 `ensureCtx()` 放在上传点击链路里并 `resume()` |
| 2 | `decodeAudioData` 会按 AudioContext 的采样率重采样 | 44.1kHz 文件在 48kHz 上下文里解码后就是 48kHz；导出采样率 = 解码后采样率，不一定是原文件采样率 |
| 3 | 段拼接处出现「咔哒」爆音 | 拼接点做淡入淡出；无用户淡变时统一加 3ms 微淡变 |
| 4 | 裁剪点停在波形中段会有爆音 | 吸附零交叉点（`snapZero`，±30ms 窗口找最近过零） |
| 5 | 倍速播放音画不同步 | 播放头时间 = `playStartTL + (ctxTime - playStartCtx) * rate`，要乘 rate |
| 6 | `OfflineAudioContext` 长度要先算好 | 总长 = `tlDur()`，按 `pos` 调度，多余长度就是静音 |
| 7 | 淡变时长 > 片段时长会行为异常 | 淡变钳制到 `min(用户值, 段时长 / 2)` |
| 8 | WAV 编码是手写的 | 44 字节 RIFF 头 + 16-bit 交织采样；注意小端、注意 clamp 到 [-1, 1] |
| 9 | `playbackRate` 只影响试听 | 导出前所有调度按 1x 重排（本项目导出恒定 1x） |

## 3. Canvas / 渲染踩坑

| # | 坑 | 做法 |
|---|---|---|
| 1 | 高分屏波形发虚 | backing store 按 `devicePixelRatio` 放大，`setTransform(dpr,0,0,dpr,0,0)`，逻辑坐标用 CSS 像素 |
| 2 | 全宽渲染长音频每列样本太多 | 每像素列聚合 min/max；样本比像素少时再逐样本画 |
| 3 | 窗口变化后画布错位 | 监听 `resize` 重设画布尺寸并重绘 |

## 4. 工程经验（本项目特有）

1. **单文件纪律**：结构/样式/逻辑全在一个 `index.html`，零依赖、不联网、无构建。这是业主强偏好，新增功能也要守住。
2. **每行代码验证必要性**：业主会逐行问「这行能不能删」。写代码默认按「可删则删」标准来。
3. **按钮可重复使用**：任何按钮不能点一次就禁用；状态切换用 toggle 语义（如淡入再点一次取消）。
4. **需求是分步小的、且会回滚**：典型模式「先加拖拽 → 再移除缩放限制 → 最后完全移除缩放」。动手前先问清楚，做快了容易白做。
5. **本地预览**：`python -m http.server <端口>`；端口被占用就换（本项目历史上换过 8765 → 8899 → 9123）。
6. **原开发网络 git clone 不通**（schannel 错误），但 `api.github.com` REST API 可用；遇到同样问题用网页上传 / REST API / 下载 ZIP 兜底。
7. **公开仓库合规**：本仓库是 public。提交前自查：无 Token、无个人绝对路径、无隐私信息；文档一律用相对路径。

## 5. 换新电脑后的建议

1. 阅读顺序：`ARCHITECTURE.md`（代码怎么组织）→ 本文（为什么这样）→ `KNOWN_ISSUES.md`（接下来可以干嘛）。
2. 拿一个真实音频文件按 `DEVELOPMENT.md` 的自检清单跑一遍，确认环境没问题。
3. 修 bug 前先在 `KNOWN_ISSUES.md` 里找是不是已知问题。
4. 想加回被移除的功能（缩放等）前，先跟业主确认——很可能是故意删的。
