# 开发与调试指南

## 1. 本地运行（两种方式）

**方式 A：直接打开（最简单）**

双击 `index.html` 用浏览器打开即可。音频是通过 `<input type="file">` 读取的，不走网络请求，所以 `file://` 协议下没有跨域问题。

**方式 B：本地静态服务器（推荐，行为更接近部署）**

```bash
# 任选一个（Python 3 通常都有）
python -m http.server 8000
# 然后浏览器访问 http://localhost:8000/index.html
```

> 端口被占用就换一个（8000 / 8080 / 8888…）。本项目没有硬编码端口。

## 2. 调试入口

- 浏览器开发者工具 → Console 看报错
- 关键对象都在全局作用域，可直接在 Console 里查看和改动：
  - `segments`（片段数组，编辑器心脏）
  - `audioBuffer`（解码后的音频）
  - `cursorTime` / `selectedId` / `viewStart` / `viewEnd`
  - `actx`（AudioContext）/ `playing`
- 验证导出结果：下载后用任意音频软件（如 Audacity）看波形、时长、首尾是否有空白

## 3. 修改后的自检清单

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 上传 WAV | 波形正常显示 |
| 2 | 上传 MP3 | 能解码、波形显示 |
| 3 | 点击画布 | 出现橙色光标 + 时间标签（mm:ss:mmm） |
| 4 | 分割 2–3 次 | 段数增加，边界线正确，各段波形连续 |
| 5 | 选中段加淡入 / 淡出 | 出现蓝色三角，再点一次取消 |
| 6 | 删除中间段 | 剩余段自动闭合，无空白 |
| 7 | 删除首段 / 尾段 | 剩余段从 0 开始 / 时间轴缩短 |
| 8 | 从光标处播放 | 从光标开始，段间无咔哒声 |
| 9 | 倍速切换 | 0.5x–3x 都正常 |
| 10 | 导出 | WAV 能下载，首尾空白已去，时长正确 |
| 11 | 淡变设 5s + 短段 | 不报错（自动钳制到段长一半） |
| 12 | 连点按钮多次 | 无卡死、无异常（按钮必须可重复使用） |

## 4. 浏览器 × 格式兼容矩阵

浏览器解码能力（`decodeAudioData`）以实际环境为准，大致规律：

| 格式 | Chrome / Edge | Firefox | Safari |
|---|---|---|---|
| WAV | 支持 | 支持 | 支持 |
| MP3 | 支持 | 支持 | 支持 |
| M4A / AAC | 支持 | 支持 | 支持 |
| FLAC | 支持 | 支持 | 支持 |
| OGG Vorbis | 支持 | 支持 | **不支持**（会解码失败） |

导出格式恒为 **16-bit PCM WAV**（所有浏览器通用）。

## 5. 新电脑恢复流程

1. 拿到代码：`git clone`，或 GitHub 网页 Download ZIP 后解压
2. 双击 `index.html`（或按方式 B 起本地服务）
3. 完事——没有依赖要装，没有构建要跑

## 6. Git 注意事项（原开发网络环境）

- 原开发网络上 `git clone github.com` 会失败（schannel 握手错误），但 `api.github.com` 可达。
  兜底方案：GitHub 网页直接上传文件 / 用 REST API / 下载 ZIP。
- 正常网络环境下 `git clone` + 常规提交推送即可。
- 仓库已启用 GitHub Pages：推送到 `main` 后，`https://gooooddayy.github.io/Audio-Editor/` 自动更新。

## 7. 提交前自查（合规）

- 不提交任何 Token / 密钥 / 密码
- 不提交个人绝对路径（如 `C:\Users\<用户名>\...`）
- 文档里引用路径一律用相对路径
- 仓库是 public，提交内容默认所有人可见
